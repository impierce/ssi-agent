# Glossary Terms

## Core Identity Concepts

### Decentralized Identifier (DID)

A globally unique, persistent identifier that does not require a centralized registry. DIDs are self-issued, cryptographically verifiable, and enable self-sovereign identity. In UniCore, DIDs are managed in the `agent_identity` bounded context.

**Related**: Credential, Holder, Issuer, Verifier

### Credential

A digitally signed assertion of one or more claims about a subject. Credentials in UniCore support multiple formats (JWT, SD-JWT) and can contain selective disclosure. Credentials are managed through the issuance and verification flows.

**Related**: Credential Subject, Claim, Proof, Verification

### Credential Subject

The entity about whom a credential makes claims. In many cases, the credential subject is also the holder (the entity possessing the credential).

**Related**: Credential, Holder, Claim

### Holder

The entity that receives, stores, and presents credentials. The holder controls the credentials in their digital wallet and decides when and to whom to present them.

**Related**: Wallet, Credential, Presentation

### Issuer

A trusted entity that creates, signs, and issues credentials to holders. In OpenID4VCI flows, the issuer defines credential types, validates credential requests, and manages credential metadata.

**Related**: Credential, Issuance, Signature

### Verifier

An entity that requests and verifies credentials from a holder. The verifier checks the credential's authenticity, validity, and meets their authorization requirements.

**Related**: Verification, Presentation, Credential

## OpenID4 Protocols

### OpenID4VCI (OpenID for Verifiable Credential Issuance)

Protocol specification defining how an issuer communicates with a wallet to issue credentials. Supports both pre-authorized and authorization code flows. Implemented in the `agent_issuance` bounded context.

**Related**: Issuance Flow, Credential Offer, Pre-authorized Code

### OpenID4VP (OpenID for Verifiable Presentations)

Protocol specification defining how a verifier requests and receives credential presentations from a holder. Enables selective disclosure and multiple credential formats. Implemented in the `agent_verification` bounded context.

**Related**: Verification Flow, Presentation, Challenge

### SIOP v2 (Self-Issued OpenID Provider v2)

Self-issued OpenID Provider specification allowing a user to act as their own identity provider. Enables direct authentication without a centralized provider.

**Related**: Authorization, Self-Issued Credentials

### Credential Offer

A message from an issuer to a holder inviting them to receive credentials. Contains credential type information, issuer metadata, and references to the issuance endpoint.

**Related**: Pre-authorized Code, Issuance Flow, OpenID4VCI

### Pre-authorized Code

A code generated by the issuer that allows a holder to obtain credentials without completing the authorization code flow. Used in direct issuance scenarios.

**Related**: Credential Offer, OpenID4VCI, Issuance Flow

## Architecture & Patterns

### Bounded Context

A domain-driven design pattern defining a clear organizational boundary around a specific business capability. Each bounded context in UniCore owns its domain model, data, and business logic.

**Examples in UniCore**:

- `agent_issuance` - Credential issuance
- `agent_holder` - Credential storage and management
- `agent_verification` - Credential verification
- `agent_identity` - DID and profile management

### CQRS (Command Query Responsibility Segregation)

Architectural pattern separating read and write operations. Commands modify state, queries read state. UniCore uses CQRS-ES (Event Sourcing) via the `cqrs-es` crate.

**Related**: Event Sourcing, Command Handler, Query

### Event Sourcing

Technique storing all changes to an application's state as a sequence of immutable events. State is derived by replaying events. Enables audit trails, temporal queries, and event-driven integration.

**Related**: CQRS, Aggregate, Event

### Aggregate

Domain-driven design pattern grouping related entities and value objects under a root entity. Aggregates maintain invariants and encapsulate business logic. Changes to aggregates result in domain events.

**Related**: Event Sourcing, Domain Event, Bounded Context

### Domain Event

An event that represents something important that happened in the domain. Domain events are immutable and named in past tense (e.g., `CredentialIssued`, `OfferCreated`).

**Related**: Event Sourcing, Aggregate, Application Service

## Credential Lifecycle

### Issuance Flow

The complete process of issuing a credential from an issuer to a holder using OpenID4VCI. Includes steps like credential offer, credential request, proof generation, and credential response.

**Related**: Credential Offer, Pre-authorized Code, OpenID4VCI

### Presentation Flow

The process of a holder presenting credentials to a verifier using OpenID4VP. The verifier requests specific claims, the holder selects credentials, and presents them with a proof.

**Related**: Presentation Request, Challenge, Proof, OpenID4VP

### Verification

The process of validating a credential's signature, checking validity dates, confirming issuer identity, and verifying any credential status. Performed by a verifier during the presentation flow.

**Related**: Verifier, Presentation, Credential Status, Proof

### Proof

Cryptographic evidence (signature) that proves control of a key. Used in both issuance (proof of key possession during credential request) and presentation (proof of credential authenticity and key control).

**Related**: Signature, Cryptography, Challenge
