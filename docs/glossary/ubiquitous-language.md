# Ubiquitous Language

This file defines the core domain concepts and terminology used in UniCore. It is the shared language between domain experts, product stakeholders, API consumers, and developers.

This glossary is **implementation-agnostic** and can be published to external documentation as-is.

---

## Core Identity Concepts

### Decentralized Identifier (DID)

A globally unique, persistent identifier that does not require a centralized registry. DIDs are self-issued, cryptographically verifiable, and enable self-sovereign identity.

**Related**: Credential, Holder, Issuer, Verifier

### Credential

A digitally signed assertion of one or more claims about a subject. Credentials support multiple formats and can contain selective disclosure—the ability for a holder to omit certain fields when presenting.

**Related**: Credential Subject, Claim, Proof, Verification

### Credential Subject

The entity about whom a credential makes claims. In many cases, the credential subject is also the holder (the entity possessing the credential).

**Related**: Credential, Holder, Claim

### Holder

The entity that receives, stores, and presents credentials. The holder controls the credentials in their digital wallet and decides when and to whom to present them.

**Related**: Wallet, Credential, Presentation

### Issuer

A trusted entity that creates, signs, and issues credentials to holders. The issuer defines credential types, validates credential requests, and manages credential metadata.

**Related**: Credential, Issuance, Signature

### Verifier

An entity that requests and verifies credentials from a holder. The verifier checks the credential's authenticity, validity, and whether it meets their authorization requirements.

**Related**: Verification, Presentation, Credential

### Wallet

A digital container that holds credentials on behalf of a holder. The wallet manages credential storage, retrieval, and presentation to verifiers.

**Related**: Holder, Credential, Presentation

### Claim

A statement or assertion made about a credential subject. Claims form the substance of a credential and typically include attributes like name, age, or professional qualifications.

**Related**: Credential, Credential Subject

### Proof

Cryptographic evidence (typically a signature or zero-knowledge proof) that validates:

- The credential was issued by the claimed issuer
- The holder possesses the credential
- The credential has not been tampered with

**Related**: Signature, Verification, Credential

### Signature

A cryptographic operation that binds a credential to its issuer, providing authenticity and non-repudiation. Signatures are verified by decoding and validating against the issuer's public key.

**Related**: Proof, Issuer, Verification

## OpenID4 Protocols

### OpenID4VCI (OpenID for Verifiable Credential Issuance)

Protocol specification defining how an issuer communicates with a wallet to issue credentials. Supports both direct issuance flows (pre-authorized codes) and interactive authorization code flows.

**Related**: Issuance Flow, Credential Offer, Pre-authorized Code

### OpenID4VP (OpenID for Verifiable Presentations)

Protocol specification defining how a verifier requests and receives credential presentations from a holder. Enables selective disclosure and support for multiple credential formats.

**Related**: Verification Flow, Presentation, Challenge

### SIOP v2 (Self-Issued OpenID Provider v2)

Self-issued OpenID Provider specification allowing a user to act as their own identity provider. Enables direct authentication without requiring a centralized identity provider.

**Related**: Authorization, Self-Issued Credentials

### Credential Offer

A message from an issuer to a holder inviting them to receive credentials. Contains credential type information and issuer metadata, providing the holder with details about what credentials are available.

**Related**: Pre-authorized Code, Issuance Flow, OpenID4VCI

### Pre-authorized Code

A short-lived code generated by the issuer that allows a holder to obtain credentials directly without completing an interactive authorization flow. Used in scenarios where the issuer can pre-authorize the credential request.

**Related**: Credential Offer, OpenID4VCI, Issuance Flow

### Challenge

A nonce or random value issued by a verifier that prevents replay attacks. The holder includes the challenge in their credential presentation proof to demonstrate freshness.

**Related**: Proof, Presentation, Verification

## Credential Lifecycle

### Issuance Flow

The end-to-end process of issuing a credential from an issuer to a holder. Typically includes credential offer, credential request, proof of possession, and credential delivery.

**Related**: Credential Offer, Pre-authorized Code, OpenID4VCI

### Issuance Request

A request from a holder (or their wallet) asking an issuer for specific credentials. The request includes proof of key possession and any required claims that the issuer needs from the holder.

**Related**: Proof, Issuance Flow, Issuer

### Presentation Flow

The end-to-end process of a holder presenting credentials to a verifier. The verifier specifies which credentials and claims are needed, the holder selects and presents them, and the verifier validates.

**Related**: Presentation Request, Challenge, Proof, OpenID4VP

### Presentation Request

A request from a verifier asking a holder to present specific credentials or claims. The request specifies what is needed, any constraints (like credential issuers or formats), and a challenge for freshness.

**Related**: Verifier, Presentation, Challenge

### Verification

The process of validating that a presented credential is:

- Authentically issued by the claimed issuer
- Not expired or revoked
- Meets the verifier's authorization requirements

**Related**: Verifier, Presentation, Proof

### Selective Disclosure

The capability for a holder to omit certain claims from a credential when presenting it to a verifier, revealing only the minimum information necessary. This enhances privacy by default.

**Related**: Credential, Presentation, Holder

### Credential Status

The current state of a credential: valid, expired, revoked, or suspended. Verifiers check credential status during verification to ensure the credential is current and not revoked by the issuer.

**Related**: Credential, Verification, Issuer

### Credential Template

A blueprint that defines what a verifiable credential should look like. A template specifies what fields the credential contains, how long it's valid, which fields can be selectively disclosed, and what credential standard it follows (e.g., Open Badges 3.0).

Issuers set up a template once and reuse it for every instance of that credential type (e.g., diplomas, membership cards, professional certifications). Templates move through states: `Draft` (being set up) → `Published` (active) → `Archived` (retired) → `Deleted` (no longer needed).

**Related**: Credential, Issuer, Selective Disclosure, Credential Lifecycle
